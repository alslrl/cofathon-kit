# 인터뷰 안내 (인터뷰 세션만 읽는다)

## 질문 목록 채우기 (시작할 때 한 번)
- README와 데이터 파일을 함께 읽고 INTERVIEW.md 질문 목록 1~3단계를 채운다. 데이터는 열 이름, 앞 몇 줄, 빈칸·중복·드문 값·0과 음수 집계만 본다(원본 행 전체를 출력하지 않는다). README에 답이 있는 건 빼고, 과제의 실제 대상 이름을 넣어 구체적으로 쓴다. 기준을 직접 묻지 않고 기준을 정하는 데 필요한 사실을 묻는다.
- 1단계 맥락: 지금 방식, 최근 사례, 오래 걸리는 부분, 불만, 예외
- 2단계 사실 파악: 데이터에서 보이는 쏠림·예외를 근거로 한 질문. 운영 규칙은 기간 예외 / 이어질 때 / 묶을 때 / 따로 다룰 대상 / 못 할 때 범주 중 README가 정하지 않은 것을 빠짐없이.
- 데이터 해석 질문도 2단계에 넣는다: 이름만으로 뜻이 애매한 열, 단위·코드값의 뜻, 빈칸이 뜻하는 것, 같은 ID가 여러 번 나오는 이유, README와 데이터가 다른 부분.
- 3단계 추가 요청: README 밖 요청이나 불편
- 질문 하나에는 물음 하나만 넣는다.
- 질문 본문은 담당자에게 그대로 보낼 수 있는 업무 말로 쓴다(파일 이름·열 이름·행 번호를 쓰지 않는다). 근거는 질문 끝 "근거:" 뒤에만 적는다.
- 2단계 질문 앞에 우선순위를 붙인다. P0은 8개 이하로, 답에 따라 규칙·계산·화면이 바뀌는 질문만 붙이고 영향이 큰 순서로 놓는다. P1은 가정하고 넘어가도 되는 질문이다. P0부터 묻는다.
- 2단계 사실 질문은 데이터로 보기를 만들 수 있으면 보기 2~3개와 "또는 다른 방식"을 붙인다. 예: "(같은 날 오후 / 다음 날부터 / 또는 다른 방식)"

## 질문하는 법
- 한 번에 하나씩 제안한다.
- 다음 질문은 이 순서로 추천한다: (1) 담당자가 먼저 꺼낸 문제·불만·사례에 대한 꼬리 질문("왜 그랬나요?", "그때 실제로 어떻게 처리했나요?") (2) 남은 P0 (3) 나머지.
- 답이 모호하면 그 답에 나온 말로 보기 2~3개를 주는 질문으로 좁힌다. 보기를 줬는데도 "상황에 따라 다르다"고 하면 데이터의 실제 사례 하나를 짚어 묻거나 역제안으로 확인한다.
- 1단계 맥락 질문에 흐린 답이 오면 좁히지 말고 체크한 뒤 넘긴다. "모른다·기억 안 난다"는 규칙·계산에 영향을 주는 질문(P0·P1)일 때만 A(가정) 후보로 적는다.
- 기준을 정했으면 가정을 드러낸 역제안으로 확인한다: "제가 이해한 건 ○○이라서 △△로 하려고 합니다. 맞을까요?"

## 붙여 넣은 대화 처리
- 원문은 대화 원문 절 끝에 그대로 덧붙인다.
- 그다음 담당자 답에서 단서를 뽑는다. 단서는 담당자가 먼저 꺼낸 문제·불만·요청·사례·사람이다(예: "방을 바꿔 달라는 요청이 많았어요"). 흐린 답 안의 단서도 뽑는다.
- 단서 질문은 답에 따라 규칙·계산·화면이 바뀔 수 있는 단서에만 만든다. 나머지 단서는 버린다.
- 한 번 붙여 넣을 때 새 단서 질문은 최대 2개까지만 만든다.
- 한 단서에서 꼬리 질문은 두 번까지 한다. 그래도 규칙이 안 나오면 역제안을 한 번 하고, 그래도 안 되면 A 후보로 적고 그 단서는 닫는다.
- 단서 질문은 파일 끝 "단서 질문" 절에 "Q번호 [단서]"로 덧붙인다. 다음 추천은 이 질문부터 Q번호로 안내한다.
- 원문을 저장한 뒤에는 대화 원문 절보다 앞에 줄을 추가하지 않는다(출처 줄 번호가 밀린다). 질문 목록은 체크와 짧은 답 표시만 같은 줄에서 고친다.
- 새 H·A·N 후보는 후보 절 끝에 번호, 필수/추가 제안, 출처 줄과 함께 적는다. REQUIREMENTS.md와 겹치면 수정안으로 적는다.

## 질문 구간 완료 알림
- 질문 구간은 1단계 / 2단계 P0 / 2단계 P1 / 3단계 넷이다(작업 묶음과 다르다).
- 붙여 넣은 대화로 한 구간의 질문이 모두 체크되면 "<구간> 완료: 메인 세션에 인터뷰 반영"이라고 알려 준다.
- 담당자가 모른다고 한 P0·P1 질문은 A 후보로 적고 체크한다. 내가 넘기라고 한 질문은 "(넘김)"을 붙여 체크한다.
