# 인터뷰 안내 (인터뷰 세션만 읽는다)

## 질문 목록 채우기 (시작할 때 한 번)
- README와 데이터 파일을 함께 읽고 INTERVIEW.md 질문 목록 1~3단계를 채운다. 데이터는 열 이름, 앞 몇 줄, 빈칸·중복·드문 값·0과 음수 집계만 본다(원본 행 전체를 출력하지 않는다). README에 답이 있는 건 빼고, 과제의 실제 대상 이름을 넣어 구체적으로 쓴다. 기준을 직접 묻지 않고 기준을 정하는 데 필요한 사실을 묻는다.
- 1단계 맥락: 지금 방식, 최근 사례, 오래 걸리는 부분, 불만, 예외
- 2단계 사실 파악: 데이터에서 보이는 쏠림·예외를 근거로 한 질문. 운영 규칙은 기간 예외 / 이어질 때 / 묶을 때 / 따로 다룰 대상 / 못 할 때 범주 중 README가 정하지 않은 것을 빠짐없이.
- 데이터 해석 질문도 2단계에 넣는다: 이름만으로 뜻이 애매한 열, 단위·코드값의 뜻, 빈칸이 뜻하는 것, 같은 ID가 여러 번 나오는 이유, README와 데이터가 다른 부분.
- 3단계 추가 요청: README 밖 요청이나 불편

## 질문하는 법
- 한 번에 하나씩 제안한다.
- 답이 모호하면 그 답에 나온 말로 보기 2~3개를 주는 질문으로 좁힌다. 그래도 모르면 A(가정) 후보로 적는다.
- 기준을 정했으면 가정을 드러낸 역제안으로 확인한다: "제가 이해한 건 ○○이라서 △△로 하려고 합니다. 맞을까요?"

## 붙여 넣은 대화 처리
- 원문은 대화 원문 절 끝에 그대로 덧붙인다.
- 새 H·A·N 후보는 후보 절 끝에 번호, 필수/추가 제안, 출처 줄과 함께 적는다. REQUIREMENTS.md와 겹치면 수정안으로 적는다.

- 실제 실행 결과의 핵심 숫자 2~3개와 확인 질문 하나로, 담당자에게 보낼 짧은 메시지를 만든다. 숫자마다 어느 결과에서 나왔는지 적는다.
