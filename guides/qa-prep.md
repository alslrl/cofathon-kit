# 서술형 대비 안내 (메인 세션이 "서술형 대비" 때만 읽는다)

- 작업 폴더의 QA_PREP.md를 아래 형식으로 채운다. 칸마다 5줄 이내, 실제 파일·함수·숫자로 쓴다. 확인하지 못한 건 "확인 안 됨"이라고 쓴다.
- 재료: 각 PLAN(원리·대안, 변경 기록, 오류 기록), 요구사항 표 상태, verify 출력, INTERVIEW.md. 필요하면 코드를 직접 확인한다.
- 다시 시키면 바뀐 부분만 고친다.

```markdown
# 서술형 대비
가장 약한 곳: (한 줄)
## 1. 핵심 방법: 고른 방법 / 더 단순한 대안 / 고른 이유 / 보장하지 못하는 것
## 2. 흐름: 입력 → 파일·함수 → 저장 상태(어디에, 누가) → 출력
## 3. 구현·검증한 것 vs 가정·미구현 + 확인할 파일·명령
## 4. 규모나 조건이 바뀌면: 깨지는 곳, 추가로 할 검증
## 5. AI 결과를 믿은 근거: 어떤 실행 결과로 확인했나
## 6. AI와 고친 문제 사례: 발견 경위 / AI 진단 / 받아들인 것·고친 것·버린 것
```

## 설명 연습 (내가 "설명 연습"이라고 하면)
- QA_PREP.md의 여섯 칸에서 질문을 하나씩 낸다. 답이나 힌트를 먼저 보여 주지 않는다.
- 내가 2~4문장으로 답하면, 실제 코드·기록과 비교해 틀리거나 빠진 부분만 짧게 짚고 다음 질문으로 넘어간다.
- 내가 "그만"이라고 하면 멈춘다. 제출을 확정한 뒤에는 하지 않는다.
