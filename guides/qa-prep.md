# 서술형 대비 안내 (메인 세션이 "서술형 대비" 때만 읽는다)

- 작업 폴더의 QA_PREP.md를 아래 형식으로 채운다. 칸마다 첫 줄에 내가 외워서 말할 핵심 한 문장을 굵게 쓰고, 파일·숫자 같은 근거는 그 아래에 둔다. 칸마다 5줄 이내(7번만 6줄), 실제 파일·함수·숫자로 쓴다. 확인하지 못한 건 "확인 안 됨"이라고 쓴다.
- "(내가 봄)"은 요구사항 표 확인 방법 칸에 "(내가 봄)"이 붙은 것만 쓴다. 나머지 검증은 "(AI 확인)"이다.
- 재료: 각 PLAN(원리·대안, 변경 기록, 오류 기록), 요구사항 표 상태, verify 출력, INTERVIEW.md. 필요하면 코드를 직접 확인한다.
- 다시 시키면 바뀐 부분만 고친다.

```markdown
# 서술형 대비
가장 약한 곳: (한 줄)
## 1. 핵심 방법: 고른 방법 / 더 단순한 대안 / 고른 이유 / 보장하지 못하는 것
## 2. 흐름: 입력 → 파일·함수 → 저장 상태(어디에, 누가) → 출력
## 3. 구현·검증한 것 vs 가정·미구현 + 확인할 파일·명령 (검증마다 "(AI 확인)" 또는 "(내가 봄)" 표시)
## 4. 규모나 조건이 바뀌면: 깨지는 곳, 추가로 할 검증
## 5. AI 결과를 믿은 근거: 어떤 실행 결과로 확인했나 ("(AI 확인)" / "(내가 봄)" 구분)
## 6. AI와 고친 문제 사례: 발견 경위 / AI 진단 / 받아들인 것·고친 것·버린 것
## 7. 가장 중요한 결정 하나: 이유 / 대안 / 약점 / 검증 / 규모가 커지면 / AI 역할 (각 한 줄)
```

## 설명 연습 (내가 "설명 연습"이라고 하면)
- QA_PREP.md의 각 칸에서 질문을 하나씩 낸다. 답이나 힌트를 먼저 보여 주지 않는다.
- 내가 2~4문장으로 답하면, 실제 코드·기록과 비교해 틀리거나 빠진 부분만 짧게 짚는다. 내 답이 질문의 하위 물음을 모두 다뤘는지도 보고, 빠진 물음이 있으면 그 물음만 짚는다. 그다음 같은 주제로 꼬리 질문을 하나 하고 넘어간다.
- 세 질문에 한 번쯤은 실제 코드와 다른 전제를 섞은 질문을 낸다(예: 없는 기능을 있다고 가정). 내가 전제를 바로잡는지 본다.
- 내가 "그만"이라고 하면 멈춘다. 제출을 확정한 뒤에는 하지 않는다.
