# 과제 지도 안내 (내가 "과제 지도"라고 하면 그 세션만 읽는다)

- README와 데이터를 읽고 작업 폴더에 TASK_MAP.md를 만든다. 다른 파일은 고치지 않는다.
- 목적은 내가 큰 그림을 한눈에 잡는 것이다. 전체 30줄 이내로 쓰고, 파일:줄 출처, 열 이름 전체 목록, 빈칸·중복 같은 품질 집계, 산출물 필드 목록은 쓰지 않는다(요구사항 표와 인터뷰 몫이다).
- 데이터는 파일별 행 수, 파일을 잇는 열, "한 건 따라가기"에 쓸 대표 1건의 관련 행만 보고, 원본 행 전체를 출력하지 않는다.
- 내가 "내가 이해한 건 이거야"라며 요약을 보내면, 틀리거나 빠진 부분만 짧게 짚는다.

````markdown
# 과제 지도
## 1. 한 문장
누가 / 무엇 때문에 / 무엇을 만드나

## 2. 큰 그림
```
[입력]                       [처리]            [결과]
파일 (한글 이름, 행 수) ─┐
파일 (한글 이름, 행 수) ─┼─→ 핵심 처리 ───→ 결과물 ─┬→ 화면·산출물 (무엇이 보이나)
파일 (한글 이름, 행 수) ─┘   (핵심 조건)            └→ 화면·산출물 (무엇이 보이나)
보조 파일 ───────────────────────────────────────────→ 어디에 쓰이나
연결: 파일.열 = 파일.열 / ...
```

## 3. 한 건 따라가기
```
대표 1건 (핵심 속성)
 → 처리 단계: 무엇을 보고 무엇이 정해지나
 → 결과·화면: 어떻게 보이나
```
(한 줄에 한 단계, 실제 값으로)

## 4. 어려운 곳
- 결과를 틀리기 쉬운 부분, 3개 이하, 한 줄씩
````
