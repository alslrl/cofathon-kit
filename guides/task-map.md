# 과제 지도 안내 (내가 "과제 지도"라고 하면 그 세션만 읽는다)

- README와 데이터를 읽고 작업 폴더에 TASK_MAP.md를 만든다. 다른 파일은 고치지 않는다.
- 한 화면 분량으로 쓴다. 데이터는 열 이름, 행 수, 키, 빈칸·중복 집계만 보고 원본 행 전체를 출력하지 않는다.
- 내가 "내가 이해한 건 이거야"라며 요약을 보내면, 틀리거나 빠진 부분만 짧게 짚는다.

```markdown
# 과제 지도
## 1. 한 문장
누가 / 무엇 때문에 / 무엇을 만드나
## 2. 큰 흐름
입력 파일 → 처리 → 결과 → 화면·산출물 (화살표 한두 줄)
## 3. 데이터 지도
| 파일 | 한 행이 뜻하는 것 | 행 수 | 키 | 어디에 쓰이나 |
파일 사이 연결: 어느 열이 어느 파일의 어느 열과 이어지는지
## 4. 한 건 따라가기
실제 데이터 한 건이 각 파일에서 어떻게 나오고, 처리 뒤 결과와 화면에서 어떻게 보이는지 (5줄 이내, 실제 값으로)
## 5. 어려운 곳
결과를 틀리기 쉬운 부분 2~3개
## 6. README 요구 → 화면·기능
요구 한 줄 → 어느 화면·기능·산출물
```
